# 00. 갭 분석 + 학습 로드맵

## 공고 원문 (자격요건/우대사항 원문 인용)

**자격요건**
- Java, Spring, AWS 기반 웹 백엔드 서비스 개발 경험이 있으신 분
- RESTful API 설계 및 개발 경험을 보유하신 분
- DB 쿼리 분석을 통한 최적화 경험이 있으신 분
- 대용량 트래픽 최적화하고 분산 처리 구현 경험이 있으신 분
- 자료구조, 운영체제, 컴퓨터 아키텍쳐, OOP 등 기본 CS 지식을 갖추신 분
- AI 도구를 개발 워크플로우에 도입하고, 그 결과물을 비판적으로 검증하며 활용해 본 경험이 있으신 분

**우대사항**
- Spring WebFlux 기반 Reactive Programming 개발 경험이 있으신 분
- 디자인패턴을 이해하여 코드에 적용할 수 있고 아키텍쳐 설계에 능숙하신 분
- 클린 코드를 작성할 줄 알며 코드 리뷰를 통한 리팩토링에 능하신 분
- 유관 부서와 원활하게 소통할 수 있는 뛰어난 커뮤니케이션 능력을 갖추신 분
- 팀의 AI 활용 방식을 정의하고 동료에게 확산시켜 본 경험이 있으신 분

**기술 스택**
- 언어/프레임워크: Java, Spring MVC
- DB: PostgreSQL, MongoDB, DynamoDB, Redis, Vector DB
- 검색: AWS OpenSearch
- 모니터링: Datadog, CloudWatch
- 데이터솔루션: Databricks
- 클라우드: AWS

**전형**: 서류 → 기술 스크리닝(온라인 30분, CS 기초 확인) → 1차 인터뷰(설계 면접 50분) → 2차 인터뷰 → 처우협의 → 입사(3개월 수습, 급여 100%)

## 갭 분석 (자가진단 기준)

경력 연차 대비 Java/Spring **직접 구현력**이 낮다고 자가진단. 즉 "무엇을 쓰는지는 안다" 수준에서 "왜 이렇게 설계했는지 설명하며 짤 수 있다" 수준으로 올리는 것이 이번 준비의 핵심 목표.

기술 스크리닝이 **CS 기초를 온라인 30분**으로 별도 검증한다는 점이 중요한 신호 — 자료구조/OS/컴퓨터구조/OOP를 얕게 아는 정도로는 통과가 불안정하므로, 이 부분은 프로젝트 실습보다 **개념 정리 + 문제풀이 위주**로 먼저 다진다.

1차 인터뷰는 "설계 면접"(50분) — 코딩 테스트가 아니라 아키텍처/트레이드오프를 말로 설명하는 자리. 따라서 토이프로젝트는 완성도보다 **설계 결정을 언어화할 수 있는 소재**로 삼는 것이 목적.

## 학습 로드맵 (요약, 상세는 README.md 표)

```
01 OOP/디자인패턴 실전 적용
        ↓
02 CS 기초 (자료구조/OS/컴퓨터구조) — 기술 스크리닝 대비, 우선순위 최상위
        ↓
03 Spring MVC / RESTful API 설계 (+ 멱등키 설계)
        ↓
04 JPA + PostgreSQL 쿼리 최적화 (+ 재고 락/레이스 컨디션)
        ↓
05 NoSQL (Redis 캐싱, MongoDB, DynamoDB, 분산 락)
        ↓
06 모놀리식 → MSA 전환 설계
        ↓
07 동시성 제어 + 실시간 동시편집(낙관적 락, OT/CRDT 개념)
        ↓
08 대용량 트래픽/분산 처리
        ↓
09 Spring WebFlux / Reactive (우대, 여유 있으면)
        ↓
10 검색 엔진 기초 / OpenSearch
        ↓
11 AI 도구 워크플로우 + 비판적 검증 (인터뷰 스토리텔링용)
```

각 문서는 "이 요구사항이 왜 나왔나 → 핵심 개념 → project/ 대응 실습 → 검색용 키워드" 구조로 작성한다.

## 프로젝트 설계 개요

가제 "미니 협업 문서 편집기 백엔드" — 채용공고 실제 업무 문구를 그대로 미러링:

- "결제, 회원, 검색 등 서비스의 근간이 되는 핵심 도메인" → member, search 도메인 실습
- "실시간 저장 및 동시 편집 기능을 구현" → document 도메인 + 낙관적 락/충돌 처리
- "MSA 전환 과정에 참여... 모놀리식 아키텍처를 마이크로서비스로 분리" → 단일 서비스로 시작해 도메인별 분리 실습

세부 설계는 02(CS 기초)까지 학습 후, `project/` 착수 시점에 확정한다.

## 참고

- saga(06번)/재고 락(04번)/결제 멱등성(03번)/Redis fallback(05번)은 예전에 다른 프로젝트에서 다뤘지만 제대로 이해하고 넘어간 게 아니었어서, 이 저장소에서 "처음 배우는 것"으로 취급하고 각 문서에서 기초부터 다시 학습한다. 이전 경험을 전제로 설명을 생략하지 말 것.
- 채용공고에 회사 기술 블로그 글이 링크돼 있다면 1차 인터뷰 전 필독 — 실제 서비스 환경에서 겪은 문제/해결 과정을 구체적으로 알 수 있어서, 면접관이 그 내용을 전제로 질문할 가능성이 있음.
