# 11. AI 도구 워크플로우 + 비판적 검증

공고 인용 자격요건: "AI 도구를 개발 워크플로우에 도입하고, 그 결과물을 비판적으로 검증하며 활용해 본 경험이 있으신 분." 우대사항: "팀의 AI 활용 방식을 정의하고 동료에게 확산시켜 본 경험이 있으신 분." 공고에 회사 기술 블로그 링크가 첨부돼 있었음(AI 활용 관련 사례 글).

이 문서는 새 기술 학습이 아니라 **인터뷰 스토리텔링 준비** 문서 — "AI 도구를 그냥 썼다"가 아니라 "왜, 어떻게, 어디까지 검증하고 썼는가"를 구체적으로 말할 수 있어야 함.

## 1. 이 자격요건이 왜 명시적으로 들어갔는가

- 이 저장소 자체가 이미 이 역량의 증거물 — Claude Code로 학습 자료/토이프로젝트를 만들면서, 생성된 코드/설명을 그대로 믿지 않고 검증하는 과정을 실제로 거치고 있다는 것 자체가 스토리텔링 소재.
- 회사가 이 항목을 명시했다는 건 "AI가 짜준 코드를 검토 없이 머지하는 사람"을 걸러내고 싶다는 신호 — 반대로 "AI를 잘 부리되 최종 책임은 내가 진다"는 태도를 보여줘야 함.

## 2. "비판적으로 검증"이 구체적으로 뭘 의미하는가 — 체크리스트

AI가 생성한 코드/설계를 받았을 때 확인해야 할 것들 (이 저장소의 `project/` 작업 시 실제로 적용할 습관):

- [ ] **동작 검증**: 실행/테스트가 실제로 통과하는가 (읽고 그럴듯하다고 넘어가지 않기)
- [ ] **엣지 케이스**: null, 빈 컬렉션, 동시성 상황(07번 문서) 등 AI가 놓치기 쉬운 경계 조건을 직접 물어보거나 테스트로 확인
- [ ] **과설계 여부**: 요구하지 않은 추상화/설정 옵션을 AI가 임의로 추가하지 않았는지 (YAGNI — 이 저장소 CLAUDE.md의 ponytail 컨벤션과 동일한 문제의식)
- [ ] **보안/성능 함정**: SQL Injection 가능성, N+1 문제(04번), 락 없는 동시성 코드(07번) 등 AI가 "일단 동작하는" 코드를 줄 때 놓치기 쉬운 부분
- [ ] **설명 가능성**: 이 코드가 왜 이렇게 짜였는지 내가 남에게 설명할 수 있는가 — 설명 못 하면 검증도 안 된 것

## 3. AI 도구를 실무 워크플로우에 넣는 실제 패턴

- **코드 생성 + 즉시 테스트 작성 요청**: 로직만 받지 않고 "이 함수의 실패 케이스 테스트도 같이 짜줘"까지 묶어서 요청 — 첨부된 기술 블로그의 AI 활용 사례가 이 패턴의 확장.
- **작은 단위로 나눠서 검증 가능하게 요청**: 거대한 기능을 한 번에 생성시키면 검증이 불가능해짐 — 함수/모듈 단위로 쪼개 받고 그때그때 확인.
- **AI에게 자기 코드 리뷰를 시키는 것과 사람이 리뷰하는 것을 구분**: AI 리뷰는 놓치는 관점(비즈니스 맥락, 팀 컨벤션)이 있으므로 최종 게이트는 사람.
- **문서화/보일러플레이트처럼 검증 비용이 낮은 작업에 먼저 활용**하고, 점차 신뢰 가능한 범위를 넓히는 방향 — 처음부터 핵심 비즈니스 로직을 전적으로 맡기지 않는 판단력.

## 4. 팀에 AI 활용 방식을 "확산"시킨다는 것 (우대사항)

- 개인 생산성 도구로 그치지 않고, **팀 차원의 규칙/컨벤션**으로 만든 경험을 말할 수 있으면 우대사항까지 커버.
- 예시로 말할 수 있는 형태: "AI가 생성한 코드에 대한 리뷰 체크리스트를 팀에 공유했다", "반복되는 보일러플레이트 작업에 AI 활용 가이드를 만들어 팀원들의 온보딩 시간을 줄였다" 류 — **실제 경험이 있다면 구체적 수치/변화**로, 없다면 이 저장소 학습 경험을 근거로 "어떻게 접근했을지"를 논리적으로 설명.

## 5. 인터뷰에서 나올 수 있는 질문 형태

- "AI 도구를 어떻게 활용하시나요?" → 위 3번 워크플로우 패턴 + 구체적 사례
- "AI가 생성한 코드를 어떻게 검증하나요?" → 2번 체크리스트를 자기 경험에 녹여서 답변
- "AI가 틀린 코드/설계를 줬던 경험이 있나요?" → 구체적 실패 사례 + 어떻게 잡아냈는지 (이런 질문에 "없다"고 답하면 오히려 검증을 안 해봤다는 신호로 보일 수 있음 — 실제로 이 저장소 작업 중 겪은 사례를 기록해뒀다가 활용)
- "AI 도구 도입에 팀이 반대하면?" → 검증 프로세스를 먼저 제안해 신뢰를 쌓는 접근

## 실습 방법

1. `project/` 진행하면서 AI(Claude Code 등)가 생성한 코드에 대해 위 체크리스트를 실제로 적용해보고, **한 번이라도 AI 제안을 거부/수정한 구체적 사례**를 메모해두기 — 인터뷰 소재로 그대로 씀
2. 공고에 첨부된 기술 블로그 글을 읽고 한 문단으로 요약 — 면접관이 그 글을 언급할 가능성 있음
3. 이력서/자기소개에 "AI 도구로 무엇을 했는지"가 아니라 "AI 도구가 준 결과를 어떻게 검증하고 무엇을 고쳤는지"가 드러나게 문장 다듬기
